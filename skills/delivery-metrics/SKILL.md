# Delivery metrics

Read repository-root `skills/global-core/SKILL.md` and
`skills/orchestrator-core/SKILL.md` fully. Apply the V2 execution policy. Work
under Governance, not a new permanent service or canonical JSON sector.

1. Read `docs/operations/delivery-lifecycle.md` and the approved project plan,
   current Issue/contract revisions and owner evidence. Reuse stable module/Task
   IDs. Phases are checkpoints inside a coherent Task, never extra Issues.
2. Read `skills/delivery-metrics/references/measurement.md`. Build a disposable,
   evidence-linked snapshot of existing artifacts. No new normative Task database.
   Keep unstarted work in the denominator. Never invent effort, tokens or dates.
3. Run `python scripts/delivery_report.py SNAPSHOT --root PROJECT` from the
   Harness checkout. Inspect stale evidence, blockers, documentation assessment,
   validation and human gates. A report calculates supplied evidence; it does not
   approve it or prove semantic truth. Reconcile with the responsible owners.
4. At every Task closure/checkpoint update the existing internal ledger and
   prepare a client-safe summary of outcomes, next steps and relevant manuals.
   TRIVIAL work uses one compact assessment in its existing outcome, not a new
   report, JSON contract, agent invocation or full lifecycle ritual.
5. Keep the installed template in the client project’s `docs/portal/` and link it
   from that project’s docs home/navigation. If the project uses Portal do Cliente, read
   `library/integrations/client-portal.md`. Prepare an allowlisted payload with
   `--format portal`. Send only after project-specific client publication approval,
   using its authorized API; never copy raw internal contracts/receipts publicly.
   Verify the response and read-back before claiming synchronization.

Return baseline/revision, formula and denominator, per-stage results, blockers,
source paths, documented limitations and prepared/published distinction in the
existing Task evidence. Do not claim a background hook runs: this is a host agent
protocol, with a deterministic read-only calculator, not an autonomous scheduler.
